# The private-to-shared contract

This is the written threat model `CIRCLE.md` §10 requires before ship, for the one Edge Function
that touches plaintext in transit: `synthesize-shared-journeys`.

It governs Shared Journeys — the path by which two private answers become one shared direction.
It is the authority. The validators in `supabase/functions/synthesize-shared-journeys/synthesis.ts`
and the tests in `synthesis_test.ts` exist to enforce this document. They do not define it, and
passing them is not the same as satisfying it.

## The contract

1. **Answers and passes remain private.** Neither person ever learns the other's choice, note,
   pass, or submission timing.
2. **Free-text notes do not influence shared output.** A note may inform nothing that either
   person can see.
3. **A proposal may reflect the journey question and permitted response signals, but may never
   attribute, compare, diagnose, quote, or closely paraphrase either person.**
4. **Both people must confirm before a proposal becomes an active shared direction or creates
   shared actions.**
5. **Validators and adversarial tests enforce this contract; they do not replace it.** A model can
   reveal private information without quoting it. Any argument that reduces to "the validator did
   not catch it" is not a defense.

## What is permitted to cross

Naming this precisely is what makes the boundary testable. The synthesis request may contain:

| Permitted | Why it is safe |
|---|---|
| The journey question (`insights.title`) | Server-generated by `refresh_shared_journey_question`. It interpolates object titles via `format()`, but only from objects already shared with both people — horizons, clusters, rhythms, ours items. |
| The option set (`insights.options`) | Server-generated product copy from the candidate CTE, e.g. `array['Make room for this','Shape it differently','Let it rest']`. Identical for both people. |
| Frozen shared evidence (`context_snapshot.evidence`, max 3) | Frozen at question creation from shared objects. Never contains private writing. |
| Each person's choice | Constrained by `submit_response` to `p_choice = any(i.options)`. A choice is a selection from a small fixed set, not free text. |

Everything else is excluded. In particular, **`responses.note` never leaves the database.**

## Why the boundary holds by construction

`submit_response` enforces `p_choice = any(i.options)`
(`supabase/migrations/20260808120000_shared_journeys_v1.sql`). Because choices are constrained to
a server-generated set, the note is the only free-text channel that could reach a model — and the
Edge Function does not select it into the model input. A model cannot leak a note it never
received.

This is the guarantee. The `private_quote` check in `validateSynthesis` still runs against notes,
but its role is a **tripwire** that proves the exclusion held, not the mechanism that provides it.
The layering is deliberate: architecture guarantees, validation detects, tests prove.

Contract §4 is likewise structural, not advisory: `confirm_shared_direction` counts confirmations
against `couple_members` and returns early unless `v_accepts >= 2`, so no `field_journeys` row and
no `field_life_items` row can exist until both people have chosen.

## Residual risk, stated honestly

Excluding notes does not reduce the risk to zero. Two things remain true:

**The model still learns which option each person picked.** Attribution ("the one who wanted room
to breathe") and comparison ("you both chose the same thing") remain expressible. This is what
contract §3 forbids and what the adversarial suite must cover. The mitigating property is that the
choice space is a small cross-product — typically 3 × 3 — so it can be tested **exhaustively**
rather than sampled. That is the direct descendant of the on-device 4 × 4 matrix test that
previously gated every PR.

**Close paraphrase is the weakest point.** A validator can catch shared n-grams; it cannot reliably
catch the same meaning in different words. Since notes are excluded from the input, the exposure
is limited to paraphrasing a *choice*, whose text both people already see in the option list.
That is a materially smaller surface than paraphrasing a note, but it is not nothing.

**A failed synthesis must fail visibly to us, not quietly to the couple.** The safe path
(`no_safe_direction` → "Let this rest") is also what an infrastructure failure degrades into, which
makes a broken system indistinguishable from a working one that had nothing safe to say. Failures
must be distinguishable in `journey_lifecycle_events`.

## What the couple is told

`README.md` must describe this accurately. Answers are **destroyed** at resolution
(`complete_journey_synthesis` deletes the `responses` rows); they are never shown to the partner,
not before submission and not after. Any wording implying answers become visible once both people
submit is wrong.

## Transit and retention

- The request goes to `api.openai.com` with `store: false`.
- The project must be zero-data-retention. This is an operational precondition, recorded in
  `WE/BACKEND_SETUP.md`, not something the code can assert.
- Diagnostics and logs are content-free by construction; `journey_lifecycle_events` records
  transitions, never copy.
- The function authenticates with the service-role key and is additionally gated by `verify_jwt`.

## Changing this document

Loosening any clause is a product decision, not an implementation detail. It requires updating
this file first, then the validators, then the adversarial suite — in that order. A change that
appears first in code is a regression regardless of what the tests say.
